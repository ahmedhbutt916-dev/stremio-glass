    34→## 1. What Prismal Is
    35→
    36→Prismal renders an iOS-style liquid glass material on Android using **OpenGL ES 2.0** inside a `GLSurfaceView`. The key property of the material is that it refracts, blurs, tints, and lights the content *underneath* it - not a static overlay, but a physically-inspired live effect driven by a GLSL fragment shader.
    37→
    38→The approach is fundamentally different from Android's native `RenderEffect` (AGSL) used by typical backdrop-blur libraries. Prismal runs in its own OpenGL context, captures the underlying view hierarchy into a bitmap, uploads it as a texture, and computes the glass appearance entirely on the GPU per fragment.
    39→

    42→## 2. High-Level Architecture
    43→
    44→```
    45→Android View Hierarchy
    46→        │
    47→        │ (View.draw → Canvas → Bitmap)
    48→        ▼
    49→  Background Capture          ← PrismalFrameLayout.scheduleCaptureBackground()
    50→        │
    51→        │ (Bitmap → GL texture upload on GL thread)
    52→        ▼
    53→  backgroundTexture (GL_TEXTURE_2D)
    54→        │
    55→        ├──────────────────────────────────────────────────┐
    56→        │                                                  │
    57→        ▼                                                  ▼
    58→  [blurHProgram]                                   [bgProgram]
    59→  Horizontal Gaussian pass                    Draw raw bitmap as
    60→  → blurTex1 / blurFbo1                       fullscreen background quad
    61→        │
    62→        ▼
    63→  [blurVProgram]
    64→  Vertical Gaussian pass
    65→  → blurTex2 / blurFbo2  (frosted texture)
    66→        │
    67→        └──────────────┐
    68→                       ▼
    69→               [glassProgram]        ← fragment_shader.glsl
    70→               SDF mask + height
    71→               Normals + refraction
    72→               Fresnel + specular
    73→               Rim / caustic / shadow
    74→               → composited glass quad
    75→```
    76→
    77→**Classes involved:**
    78→
    79→| Class | Role |
    80→|---|---|
    81→| `PrismalFrameLayout` | Android `FrameLayout` host; owns the `GLSurfaceView`, triggers background capture, exposes the public API |
    82→| `PrismalGlassRenderer` | `GLSurfaceView.Renderer`; manages all GL state, shader programs, FBOs, and uniform uploads |
    83→| `fragment_shader.glsl` | The main glass fragment shader - all the optics math lives here |
    84→| `PrismalLiquidGlass` | Singleton with the canonical default parameter set (the iOS-calibrated recipe) |
    85→| `SpringAnimator` | Choreographer-driven spring for smooth physics animations |

    89→## 3. Background Capture Pipeline
    90→
    91→The glass must refract real content beneath it. The problem: `GLSurfaceView` renders into a separate EGL surface that composites at the OS level - it cannot read pixels from the regular Android `Canvas` pipeline directly.
    92→
    93→**Solution:** `PrismalFrameLayout` draws the view hierarchy above it (its parent's background plus sibling views) into a `Bitmap` using `View.draw(canvas)`, then uploads that bitmap to a GL texture on the GL thread.
    94→
    95→```kotlin
    96→// PrismalFrameLayout - simplified capture flow
    97→fun scheduleCaptureBackground() {
    98→    if (captureScheduled) return   // deduplication flag
    99→    captureScheduled = true
   100→    post {
   101→        captureScheduled = false
   102→        val bitmap = Bitmap.createBitmap(width, height, Bitmap.Config.ARGB_8888)
   103→        val canvas = Canvas(bitmap)
   104→        // walk up to root, translate so this view is at (0,0)
   105→        parent?.draw(canvas)
   106→        glSurface.queueEvent {
   107→            renderer.setBackgroundTexture(bitmap)  // uploads & recycles
   108→            glSurface.requestRender()
   109→        }
   110→    }
   111→}
   112→```
   113→
   114→The `captureScheduled` flag prevents redundant captures when multiple events fire in the same frame (scroll + layout change, for example).
   115→
   116→**Y-axis flip:** Android's `Canvas` has origin top-left; OpenGL has origin bottom-left. The vertex shader flips the `v_shapeCoord` Y so textures sample correctly without an extra blit.

   120→## 4. Two-Pass Gaussian Blur
   121→
   122→The frosted-glass frost effect uses a separable Gaussian blur applied to the captured background. Separating an N×N Gaussian into a horizontal and a vertical 1D pass reduces sample count from O(N²) to O(2N).
   123→
   124→**Pass 1 - Horizontal** (`prismal_blur_h`):  
   125→Reads `backgroundTexture` → writes `blurTex1` (via `blurFbo1`).
   126→
   127→**Pass 2 - Vertical** (`prismal_blur_v`):  
   128→Reads `blurTex1` → writes `blurTex2` (via `blurFbo2`).
   129→
   130→The glass shader then reads from:
   131→- `u_backgroundTexture` - the raw (sharp) texture, used for refraction rays that exit through the front face
   132→- `u_blurredTexture` - the frosted texture, selected when `u_useBlurredTexture == 1`
   133→
   134→The blur sigma is driven by `blurRadius` (in pixels). Higher = more frosted.
   135→

   138→## 5. Signed Distance Fields
   139→
   140→A **Signed Distance Field (SDF)** is a scalar function `f(p)` that returns the signed distance from point `p` to the nearest surface of a shape - negative inside, zero on the boundary, positive outside.
   141→
   142→Prismal uses two SDF variants for the rounded rectangle:
   143→
   144→### `sdRoundedRectRealistic` - exact, per-quadrant radius
   145→
   146→```glsl
   147→float sdRoundedRectRealistic(vec2 coord, vec2 halfSize, float radius) {
   148→    vec2 cornerCoord = abs(coord) - (halfSize - vec2(radius));
   149→    float outside = length(max(cornerCoord, 0.0)) - radius;
   150→    float inside  = min(max(cornerCoord.x, cornerCoord.y), 0.0);
   151→    return outside + inside;
   152→}
   153→```
   154→
   155→`abs(coord)` folds all four quadrants into one (top-right), subtracts the inner rectangle extent `(halfSize - radius)`, then uses `length(max(..., 0))` for the rounded corner arc and `min(max(...), 0)` for the interior. It supports per-quadrant radii by calling `radiusAtCentered` before the call to pick the right radius for the fragment's corner.
   156→
   157→### `sdRoundBox` - smooth-min version
   158→
   159→```glsl
   160→float sdRoundBox(vec2 p, vec2 b, float r, float k) { ... }
   161→```
   162→
   163→Uses `smax_poly` / `smin_poly` (polynomial smooth-min/max) for the corner join. The `k` parameter controls blending radius - higher = softer, rounder corners at the join. This is used for the height field and opacity mask because smoothed edges look better for the ramp profile.
   164→
   165→### `gradSdRoundedRectRealistic` - analytic gradient
   166→
   167→The analytic gradient of the SDF (the outward normal in 2D screen space) is used to:
   168→- Drive the lens distortion direction
   169→- Define the `outward` vector (pointing away from the shape centre, following the rounded-rect iso-curves)
   170→- Compute the `gN` normal for rim highlight orientation
   171→

   174→## 6. Height Field - The Glass Slab
   175→
   176→The glass is modelled as a **height field** `h(p)` - a 2D function over the glass quad that represents the physical thickness of the glass at each pixel. Where `h = 1` the glass is at full depth (centre of a dome); where `h = 0` the glass is at the silhouette edge (zero thickness).
   177→
   178→This height field is what produces the lens curvature, specular highlights, and normal map - everything that makes the glass look three-dimensional.
   179→
   180→### Circular arc profile (`getHeightFromDist`)
   181→
   182→```glsl
   183→float getHeightFromDist(float dist, float tw) {
   184→    float t = clamp(-dist / tw, 0.0, 1.0);
   185→    return sqrt(max(0.0, 2.0 * t - t * t));
   186→}
   187→```
   188→
   189→`dist` is the SDF value (negative inside the shape). `tw` is the transition width - the pixel-space ramp length over which height rises from 0 to 1.
   190→
   191→The formula `sqrt(2t - t²)` is a **circular arc**: it maps the normalised depth `t ∈ [0,1]` through one quarter of a unit circle, giving:
   192→
   193→- `t = 0` (silhouette edge) → `h = 0` - the glass has zero thickness here
   194→- `t = 1` (fully inside) → `h = 1` - maximum depth
   195→- The derivative `dh/dt = (1-t)/sqrt(2t-t²)` is steep near the edge and flattens toward the centre - exactly the profile of a meniscus or water droplet viewed from above
   196→
   197→Previously a logistic sigmoid was used (`1 / (1 + exp(...))`), which gave `h ≈ 0.25` at the silhouette rather than 0. That residual height made the edge feel flat and linear - the sigmoid never truly reached zero. The circular arc guarantees `h = 0` at the exact silhouette, producing the sharp, clean water-droplet edge curvature.
   198→
   199→### Dome mode (`u_liquidDome`)
   200→
   201→When `u_liquidDome > 0`, the height field blends between two models:
   202→
   203→**Slab mode (`dome = 0`):** `hSlab` - the SDF-ramp profile, producing a flat top with curved edges. Like a glass disc.
   204→
   205→**Dome mode (`dome = 1`):** `hDome` - built from `tShell` (normalised distance from edge to centre):
   206→
   207→```glsl
   208→float hCap    = pow(tShell, 0.88);          // spherical cap profile
   209→float edgeBulge = 0.24 * pow(tShell, 2.45); // surface-tension bulge at contact line
   210→float hDome   = (hCap + edgeBulge) * meniscusBand;
   211→```
   212→
   213→The result looks like a sessile water droplet: a curved dome with a slight bulge at the contact line where the liquid meets the surface.
   214→
   215→The `tw` (transition width) also widens proportionally with dome strength:
   216→
   217→```glsl
   218→float tw = max(u_heightTransitionWidth * (1.0 + 0.38 * dome) + minDim * 0.085, 1.0);
   219→```
   220→
   221→A stronger dome needs a wider edge ramp.
   222→

   225→## 7. Spherical Meniscus - Water Droplet Curvature
   226→
   227→The surface normal at the silhouette of a water droplet does not point straight up - it curves outward and downward at the contact angle. This is the **meniscus** effect that makes water droplets and real glass look spherical rather than like cut cylinders.
   228→
   229→After computing the gradient-derived normal `N`, a meniscus normal `N_meniscus` is blended in at the rim zone:
   230→
   231→```glsl
   232→float menW     = clamp(edgeDist / tw, 0.0, 1.0);          // 0 at edge, 1 deep inside
   233→float menCirc  = sqrt(max(0.0, 1.0 - menW * menW));       // circular arc: steep at edge
   234→vec3 N_meniscus = normalize(vec3(-outward * menCirc * 0.95, 0.26 + 0.74 * menW));
   235→float menBlend  = smoothstep(tw * 0.5, 0.0, edgeDist)     // active only near silhouette
   236→                * smoothstep(-6.0, 0.0, distMask) * 0.82;
   237→N = normalize(mix(N, N_meniscus, menBlend));
   238→```
   239→
   240→`N_meniscus` points radially outward (in the `outward` direction) at the silhouette with the Z component starting low (nearly horizontal, like the side of a sphere) and rising toward vertical as you move inward. `menCirc` traces a quarter-circle cross section.
   241→
   242→This is what makes the sides of the glass appear **spherically curved** rather than flat vertical walls.

   246→## 8. Surface Normals
   247→
   248→The surface normal `N` is computed from the height field gradient via finite differences (central differences, 1-pixel step):
   249→
   250→```glsl
   251→vec2 computeGradientHeight(vec2 pPx, vec2 halfSz, float cr, float k, float tw) {
   252→    float hpx = getHeightFromDist(sdRoundBox(pPx + vec2(1,0), halfSz, cr, k), tw);
   253→    float hnx = getHeightFromDist(sdRoundBox(pPx - vec2(1,0), halfSz, cr, k), tw);
   254→    float hpy = getHeightFromDist(sdRoundBox(pPx + vec2(0,1), halfSz, cr, k), tw);
   255→    float hny = getHeightFromDist(sdRoundBox(pPx - vec2(0,1), halfSz, cr, k), tw);
   256→    return vec2((hpx - hnx) * 0.5, (hpy - hny) * 0.5);
   257→}
   258→```
   259→
   260→The 3D normal is then:
   261→
   262→```glsl
   263→vec3 N = normalize(vec3(-gradH.x * normalStrength, -gradH.y * normalStrength, 1.0));
   264→```
   265→
   266→The negative sign makes the normal point away from the surface for a dome (the slope rises toward the centre, so the gradient points inward, and the negated gradient points the normal outward/upward). The Z component `1.0` keeps the normal generally pointing toward the viewer. `u_normalStrength` scales the XY tilt to control how "steep" the glass looks.
   267→
   268→After computing N, the meniscus blend is applied (see §7), then the debug `u_showNormals` path can visualise N as `(N * 0.5 + 0.5)` - a standard normal-map colour encoding.

   272→## 9. Snell's Law Refraction
   273→
   274→Real glass bends light at its surfaces according to **Snell's law**:
   275→
   276→```
   277→n₁ sin(θ₁) = n₂ sin(θ₂)
   278→```
   279→
   280→where `n` is the index of refraction (IOR) and `θ` is the angle to the surface normal. Air has IOR ≈ 1.0; soda-lime glass ≈ 1.52; water ≈ 1.33.
   281→
   282→In the shader, `refract()` is GLSL's built-in implementation of Snell's law. The glass is modelled as a slab with two refractive interfaces: air → glass (entry) and glass → air (exit):
   283→
   284→```glsl
   285→vec3 V    = vec3(0.0, 0.0, 1.0);          // view direction (straight down)
   286→vec3 refIn  = refract(-V, N, 1.0 / u_ior);    // ray enters glass from above
   287→vec3 refOut = refract(refIn, -N, u_ior);       // ray exits glass from below
   288→vec2 snellOff = refOut.xy * u_glassThickness * refrStr / u_resolution * u_displacementScale;
   289→```
   290→
   291→`refOut.xy` is the lateral displacement of the ray after passing through the full slab. `u_glassThickness` is the physical slab thickness in pixels - a thicker slab produces more displacement for the same IOR.
   292→
   293→`refrStr` modulates strength by height and Fresnel:
   294→
   295→```glsl
   296→float refrStr = height * (0.5 + F * 0.35);
   297→```
   298→
   299→Pixels near the silhouette (`height ≈ 0`) see almost no Snell displacement; the bright Fresnel rim pixels (`F` high) see slightly amplified displacement.

   303→## 10. Lens Distortion and Parallax
   304→
   305→Beyond Snell refraction there are two more UV offset contributions:
   306→
   307→### Lens distortion (`dLens`)
   308→
   309→Lens distortion pushes pixels near the silhouette inward (barrel) or outward (pincushion) based on the SDF depth. The `circleMapRealistic` function maps the ramp nonlinearly:
   310→
   311→```glsl
   312→float circleMapRealistic(float x) {
   313→    return 1.0 - sqrt(max(0.0, 1.0 - x * x));  // quarter-circle ease-out
   314→}
   315→```
   316→
   317→The distortion is applied along `lensDir` - the SDF gradient blended slightly toward the shape centre to give a compound "barrel through a fisheye" look.
   318→
   319→### Parallax (`parallax`)
   320→
   321→Parallax fakes the stereo depth of the glass by offsetting the UV based on the surface tilt (via `gradLens`) and height:
   322→
   323→```glsl
   324→vec2 parallax = (gradLens * height * (7.0 + 22.0 * F)) / u_resolution * parallaxK;
   325→```
   326→
   327→Where the Fresnel factor `F` is high (grazing angle - silhouette), parallax increases strongly, making the edge feel physically deep. Where `F` is low (face-on centre), parallax is subtle.
   328→
   329→### Combined offset
   330→
   331→All three contributions sum into `baseOffset`:
   332→
   333→```glsl
   334→vec2 baseOffset = lensDeltaUv + snellOff + bulgeUv;
   335→```
   336→
   337→`bulgeUv` adds a subtle inward push at the glass centre (the `bulge` term), mimicking how a convex lens magnifies slightly around the middle.
   338→
   339→The whole `baseOffset` is then scaled by `pxNorm` - a normalisation factor clamped to `[0.36, 1.0]` that ensures small glass elements don't over-displace and large hero panels get proportionally more effect.
   340→

   343→## 11. Chromatic Aberration and Dispersion
   344→
   345→Real glass has a different IOR for each wavelength - red bends less than blue. This is **chromatic dispersion**, and it creates the coloured fringes visible at the edges of thick glass.
   346→
   347→When `u_chromaticAberration > 0`, the shader samples three separate UV coordinates and assembles them into a single RGB:
   348→
   349→```glsl
   350→vec2 dispDir  = normalize(gradLens);     // radially outward from centre
   351→vec2 chromaPush = dispDir * (chromaBase + realChroma) * pxNorm;
   352→vec2 uvR = baseOffset + chromaPush * u_dispersionR;   // red shifts outward
   353→vec2 uvG = baseOffset;                                // green stays centred
   354→vec2 uvB = baseOffset - chromaPush * u_dispersionB;   // blue shifts inward
   355→```
   356→
   357→`u_dispersionR` and `u_dispersionB` are independent multipliers (defaults = 1.0), letting you model asymmetric glass dispersion (e.g. heavy flint glass has stronger blue shift).
   358→
   359→The cross-pattern chroma term adds an extra diagonal push proportional to `(x·y) / (halfW · halfH)` — aberration that matches the corner distortion visible in real wide-angle lenses.
   360→
   361→The effect is gated by `edgeFac = pow(smoothstep(chromaFar, 0, edgeDist), 1.8)` - aberration only appears near the silhouette where thickness (and therefore dispersion) is maximum.
   362→

   365→## 12. Fresnel Effect
   366→
   367→The **Fresnel equations** describe how much light is reflected vs transmitted at a dielectric surface as a function of the angle of incidence. At normal incidence (looking straight at the glass face) most light transmits; at grazing incidence (viewing from the edge) most light reflects.
   368→
   369→Prismal uses the **Schlick approximation**:
   370→
   371→```glsl
   372→float r0 = pow((1.0 - u_ior) / (1.0 + u_ior), 2.0);   // reflectance at normal incidence
   373→float F  = r0 + (1.0 - r0) * pow(1.0 - cosVNeff, 5.0);
   374→```
   375→
   376→`r0` for IOR 1.52 (glass) ≈ 0.043 - about 4% reflectance straight-on.
   377→At the silhouette, `cosVNeff → 0`, so `F → 1` (nearly 100% reflection).
   378→
   379→`cosVNeff` is artificially pushed toward a small value near the silhouette (`edgeSil`) and where the surface normal tilts strongly sideways (`tiltW`), to exaggerate the grazing-angle rim glow on a flat panel (which would otherwise never reach true grazing angle since the viewer is always looking straight down).
   380→
   381→`F` feeds into:
   382→- Parallax strength - more depth illusion where reflection is strong
   383→- Refraction strength - less transmitted light where reflection takes over
   384→- Rim diffuse / veil highlights - the Fresnel-gated bright edge ring
   385→- Shadow and specular weights
   386→

   389→## 13. Lighting Model
   390→
   391→### Light directions
   392→
   393→Two lights are used - the primary key light `Lp` and a secondary fill `Ls`:
   394→
   395→```glsl
   396→vec3 Lp = normalize(vec3(u_lightDir, 1.45));
   397→vec3 Ls = normalize(vec3(-u_lightDir.x * 0.62 + 0.41, -u_lightDir.y * 0.62 + 0.33, 0.74));
   398→```
   399→
   400→`Ls` is derived from `Lp` with partial negation and an offset - it acts as a soft fill from the opposite-upper direction, avoiding a completely dark shadow side.
   401→
   402→### Blinn-Phong dual specular
   403→
   404→Half-vectors `Hp` and `Hs` are computed for each light:
   405→
   406→```glsl
   407→vec3 Hp = normalize(Lp + V);
   408→vec3 Hs = normalize(Ls + V);
   409→float specP = pow(max(dot(N, Hp), 0.0), shininess) * specular * 1.05;
   410→float specS = pow(max(dot(N, Hs), 0.0), shininess * 0.68) * specular * 0.48;
   411→```
   412→
   413→The secondary specular uses a broader exponent (`shininess * 0.68`) and lower intensity (`0.48x`), producing a wider, softer secondary highlight. Both are height-gated (`0.32 + 0.68 * height`) to suppress highlights near the silhouette where the glass is thin. The specular tint `vec3(0.99, 0.993, 1.0)` is a very slight cool white - real glass specular is almost colourless with a faint blue shift.

   417→## 14. Rim and Border Highlights
   418→
   419→This is the most distinctive visual feature of iOS liquid glass - bright highlights along the borders. Prismal has five layered contributions:
   420→
   421→### `rimDiffuse` - Fresnel-gated shell glow
   422→
   423→```glsl
   424→float rimDiffuse = FedgeRim * schlickW * shellRim * u_rimStrength * (0.1 + 0.34 * wrapAlong) * depthFade;
   425→```
   426→
   427→`FedgeRim = pow(1 - cosVN, 3.25)` - strongest at grazing. `schlickW = F`. `shellRim` - a band that falls off inward from the silhouette. `wrapAlong` - a tangential component that boosts corners where the light direction runs along the border (like light wrapping around a cylinder).
   428→
   429→### `rimInnerVeil` - soft interior haze
   430→
   431→A second, wider Fresnel glow (`Fnv * schlickW * shellInner`) using a broader band (`shellInner`) to add depth to the frosted interior near edges.
   432→
   433→### `rimCorner` - corner streak
   434→
   435→`streakOpp` encodes which pair of opposite corners is lit by the current `u_lightDir`:
   436→
   437→```glsl
   438→float tl = max(0, min(-cn.x, -cn.y));  // top-left weight
   439→float pairOpp = pow(mix(tl + br, trc + bl, lightDiag), 1.06);
   440→```
   441→
   442→`runAlong * max(sx, sy)` gives exponential fall-off perpendicular to the streak axis - creating a sharp diagonal highlight through the lit corners as if light skims along the glass edge.
   443→
   444→### `rimBothBorders` - the opposite-side highlight
   445→
   446→```glsl
   447→float borderAlign = pow(abs(dot(gN, Lxy)), 1.0);
   448→color += hiSoft * rimBothBorders * edgePunch;
   449→```
   450→
   451→`abs(dot(gN, Lxy))` - the absolute value of the dot product between the SDF gradient and the light direction. Using `abs` makes this **maximum on BOTH the lit border AND the opposite border** (the one facing 180° away from the light). This is a defining characteristic of iOS-style liquid glass — real backlit glass shows a highlight on the shaded side because light enters the glass, total-internally-reflects, and exits the opposite face.
   452→
   453→### `rimLitSide` - lit-side emphasis
   454→
   455→```glsl
   456→float litAlign = pow(max(0.0, dot(gN, Lxy)), 1.3);
   457→```
   458→
   459→Without `abs`, this only fires on the lit border - an additional, slightly stronger boost on the primary lit edge.
   460→
   461→### `faceSheenSoft` - face-on sheen
   462→
   463→A soft glow on the glass face where the surface normal tilts toward the light:
   464→
   465→```glsl
   466→smoothstep(-0.08, 0.74, dot(N.xy, -Lxy)) * Fnv * schlickW * u_rimStrength * 0.038
   467→```
   468→
   469→This adds the subtle brightness gradient across the glass face that makes it look rounded even at the centre.
   470→
   471→---
   472→
   473→## 15. Caustics
   474→
   475→A caustic is the bright pattern of focused light on a surface beneath a glass object (the sparkly patterns at the bottom of a swimming pool). In 2D, it approximates as a specular-like inner glow where the surface normal aligns with the key light:
   476→
   477→```glsl
   478→float causticDot = dot(normalize(vec3(gradH * u_normalStrength, 0.45)), Lp);
   479→float caust = pow(max(causticDot, 0.0), 7.0) * u_causticIntensity * height;
   480→color += caust * vec3(1.0, 0.96, 0.90);
   481→```
   482→
   483→The warm tint `(1, 0.96, 0.90)` mimics the warm-white colour of focused sunlight through glass. Gating by `height` keeps caustics away from the silhouette where the glass is thin and light doesn't focus.
   484→
   485→---
   486→
   487→## 16. Shadow
   488→
   489→An inner shadow along the glass interior edge mimics the dark zone visible where thick glass blocks light from reaching the surface below:
   490→
   491→```glsl
   492→float innerShadow = 1.0 - smoothstep(0.0, shadowFalloff, edgeDist);
   493→innerShadow = pow(innerShadow, 2.0) * 0.85 * (0.28 + height * 0.72);
   494→color = mix(color, u_shadowColor.rgb * 0.25, innerShadow * u_shadowColor.a);
   495→```
   496→
   497→`shadowFalloff = avgDim * shadowExt` where `shadowExt` is derived from `u_shadowSoftness`:
   498→- `softness ≤ 1` → `shadowExt = mix(0.15, 0.60, softness)` - moderate fall-off
   499→- `softness > 1` → `shadowExt = mix(0.15, 0.60, softness / 20)` - softness is treated as a wide diffuse spread
   500→
   501→`pow(..., 2.0)` makes the shadow fall off quadratically from the edge - a softer, more physically-plausible decay than linear.
   502→
   503→---
   504→
   505→## 17. Vibrancy
   506→
   507→The background content visible through the glass is passed through a vibrancy filter before all lighting is added:
   508→
   509→```glsl
   510→vec3 applyVibrancy(vec3 rgb, float sat) {
   511→    float L = dot(rgb, vec3(0.213, 0.715, 0.072));  // luminance (Rec.709)
   512→    return clamp(mix(vec3(L), rgb, sat), 0.0, 1.0);
   513→}
   514→color = applyVibrancy(color, u_vibrancy);
   515→```
   516→
   517→This is a simple **chroma boost**: it interpolates between the greyscale luminance and the original colour by `sat`. Values above 1.0 push colours beyond their natural saturation. Prismal uses `u_vibrancy = 1.28` (hardcoded), matching the characteristic "pumped" saturation of Apple's vibrancy effect. iOS liquid glass never shows dull content through the frosted pane.
   518→

   521→## 18. Spring Physics Animator
   522→
   523→The slider, switch, and other animated controls use `SpringAnimator` - a lightweight Hooke's law spring integrated per display frame via `Choreographer`:
   524→
   525→```
   526→F = -k(x - target) - d·v      (spring force = restoring + damping)
   527→v += F · dt
   528→x += v · dt
   529→```
   530→
   531→Parameters:
   532→- `k` = stiffness (resistance to displacement from target)
   533→- `d = 2 · dampingRatio · √k` (critical damping formula - ensures smooth settling)
   534→- `threshold` (default 0.001) - stops the animation when both position error and velocity are negligible
   535→
   536→**Choreographer** provides frame-locked callbacks (`postFrameCallback`) - each frame the spring steps one `dt` forward based on the real elapsed nanoseconds, capped at 48ms to prevent large jumps after the screen is off.
   537→
   538→The three spring instances used by each control:
   539→
   540→| Spring | damping | stiffness | Purpose |
   541→|--------|---------|-----------|---------|
   542→| `posSpring` | 1.0 | 1000 | Thumb position (critically damped - no overshoot) |
   543→| `pressSpring` | 1.0 | 1000 | Press state → glass opacity / optics transition |
   544→| `scaleXSpring` | 0.6 | 250 | Thumb X scale (underdamped - slight overshoot for bounce) |
   545→| `scaleYSpring` | 0.7 | 250 | Thumb Y scale (underdamped) |
   546→
   547→### Velocity squish
   548→
   549→While dragging, normalised drag velocity `normVel = xVelocity / travelPx` modulates the scale:
   550→
   551→```kotlin
   552→val sx = scaleXSpring.value / (1f - v * 0.75f)   // elongate along motion
   553→val sy = scaleYSpring.value * (1f - abs(v) * 0.25f) // compress perpendicular
   554→```
   555→
   556→This produces the "squish" deformation: the thumb stretches forward into the direction of motion and squishes perpendicular to it - the same organic deformation seen in iOS animations.
   557→

   560→## 19. Component Design - Slider, Switch, IconButton
   561→
   562→### PrismalSlider
   563→
   564→```
   565→FrameLayout (PrismalSlider)
   566→├── TrackView (custom View)    ← 6dp capsule, draws bg + fill rects in onDraw
   567→└── PrismalFrameLayout (thumb) ← 40×24dp, gravity=CENTER_VERTICAL
   568→    └── View (white overlay)   ← alpha=1 at rest, fades to 0 on press
   569→```
   570→
   571→- The white overlay sits above the GLSurface (which renders behind the Window surface) and is used to hide the glass at rest, revealing it only when the user presses — a white rect whose alpha fades from `1f` to `0f` as press progress increases.
   572→- Background capture (`thumb.updateBackground()`) is called on every `ACTION_MOVE` event. The `captureScheduled` deduplication flag inside `PrismalFrameLayout` ensures only one capture per frame even if many events arrive.
   573→
   574→### PrismalSwitch
   575→
   576→```
   577→FrameLayout (PrismalSwitch, gravity=CENTER_VERTICAL for children)
   578→├── TrackView (custom View)    ← 64×28dp (proportional to psw_trackHeight)
   579→│   └── lerpColor(offColor, onColor, fraction) drawn in onDraw
   580→└── PrismalFrameLayout (thumb) ← 40×24dp, gravity=CENTER_VERTICAL
   581→    └── View (white overlay)
   582→```
   583→
   584→- `fraction ∈ [0,1]` is the live animated value (driven by `posSpring`). The track colour and thumb X position are both keyed to `fraction` so the colour crossfade is perfectly in sync with thumb travel.
   585→- `travelPx = trackW - thumbW - 2·padPx = 64 - 40 - 4 = 20dp` of horizontal drag travel.
   586→- Tap vs drag: if `|rawX - dragStartX| > touchSlop` → drag mode (snap to nearest 0/1 on release). Otherwise → toggle mode (invert `isOn`).
   587→
   588→### PrismalIconButton
   589→
   590→- Calls `PrismalLiquidGlass.applyBase()` first to get the full optical recipe, then overrides with values scaled for a small (~52dp) circle.
   591→- Critical override: `setThickness(dp(5f))` - the base sets 18dp which exceeds the half-height of a 52dp circle, collapsing the entire shape into the edge ramp (looks like a thick border).
   592→- Press animation uses `ValueAnimator` to scale and pulse `normalStrength` (`8f * strength` on press) for the "glass activating" visual.
   593→

   596→## 20. Key Parameter Reference
   597→
   598→| Parameter | Uniform / Field | What it controls |
   599→|---|---|---|
   600→| `u_ior` | IOR | Snell deflection angle - higher = stronger bend. 1.3 (water) to 1.9 (heavy glass) |
   601→| `u_heightTransitionWidth` | `setThickness()` | SDF ramp width in pixels. **Must be < ~40% of `minDim`** or entire shape is a border |
   602→| `u_heightBlurFactor` | `setHeightBlurFactor()` | Depth-of-field blur gradient width. Proportional to view size (~25%) |
   603→| `u_normalStrength` | `setNormalStrength()` | XY normal tilt scale - higher = steeper, sharper glass |
   604→| `u_displacementScale` | `setDisplacementScale()` | Final UV offset multiplier applied to all refraction contributions |
   605→| `u_liquidDome` | `setLiquidDomeStrength()` | 0 = flat slab, 1 = spherical sessile droplet |
   606→| `u_fresnelReflect` | `setFresnelReflectStrength()` | Multiplier on Schlick F used for rim/parallax (0–2) |
   607→| `u_rimStrength` | `setRimStrength()` | Master scale for all rim/border highlight contributions |
   608→| `u_lensRefractionPx` | computed | Pixel-space lens displacement magnitude (auto-computed from size+IOR+thickness) |
   609→| `u_lensRefractionScale` | `setLensRefractionScale()` | User scale on the computed lens px value |
   610→| `u_blurRadius` | `setBlurRadius()` | Gaussian sigma for frosted blur pass |
   611→| `u_chromaticAberration` | `setChromaticAberration()` | RGB channel split in pixels; 0 disables entirely |
   612→| `u_specular` / `u_shininess` | `setSpecular()` | Blinn-Phong intensity and glossiness exponent |
   613→| `u_causticIntensity` | `setCausticIntensity()` | Strength of focused-light caustic inner glow |
   614→| `u_transmittance` | `setTransmittance()` | Final alpha multiplier (0 = invisible, 1 = opaque glass) |
   615→| `u_shadowSoftness` | `setShadowProperties()` | ≤1 = hard shadow, >1 = soft (value ÷ 20 for wide spread) |

   619→## 21. Critical Sizing Rule
   620→
   621→The most common mistake when applying Prismal to small controls is setting `thickness` (i.e. `u_heightTransitionWidth`) to a value appropriate for a large card and not scaling it down.
   622→
   623→**The shader computes:**
   624→
   625→```glsl
   626→float tw = max(u_heightTransitionWidth * (1.0 + 0.38 * dome) + minDim * 0.085, 1.0);
   627→```
   628→
   629→If `tw ≥ minDim` (the half-height of the shape), the entire shape is inside the edge ramp - every pixel reads as "near the silhouette edge" and the glass looks like a uniform glowing ring, not a glass object.
   630→
   631→**Rule of thumb:**
   632→
   633→```
   634→u_heightTransitionWidth  ≤  0.35 × (min(width, height) / 2)
   635→```
   636→
   637→| View size | Max sensible thickness |
   638→|---|---|
   639→| 24dp thumb (slider/switch) | ≈ 4dp |
   640→| 52dp icon button | ≈ 5–6dp |
   641→| 100dp card | ≈ 12–16dp |
   642→| 200dp hero card | ≈ 20–28dp |
   643→
   644→`PrismalLiquidGlass.applyBase()` uses 18dp - correct for large cards, but it must be overridden for any view smaller than ~100dp.
